How client data is handled.

Plain words, no diagram required. This page describes the standing policy for every engagement; each client's written agreement restates it.

How records move

Your existing systems remain the official record. VNMSFX reads only the records and periods named in the agreement. Findings, evidence links, exception lists and drafts are written only to the client-owned output workspace named before work begins.

CLIENT-OWNED SOURCES   ↓  standard workflows read the agreed records APPROVED PROCESSING   ↓  findings, evidence links, exception lists and drafts CLIENT-OWNED OUTPUT WORKSPACE   ↓  named human review CLIENT ACTION

Access uses a named collaborator, a dedicated client-owned service identity, an approved OAuth connection or an export the client creates. VNMSFX never asks for or uses an employee's shared password.

When a provider cannot technically enforce read-only access, that limitation is disclosed in writing. The client may approve a tested query-only route or use recurring exports instead.

Access

  • Only the systems, records and periods named in the agreement are used.
  • Access is provided through a named collaborator account, a dedicated client-owned service identity, an approved OAuth connection or a client-created export. VNMSFX never asks for or uses a shared employee password.
  • Standard workflows read the agreed source records. Approved outputs are written only to named client-owned destinations. Any technically broader permission is disclosed and approved, or the client supplies recurring exports.
  • Each grant is revocable in the system that issued it. Offboarding follows and verifies a provider-by-provider checklist — not a single switch — and ends in a written receipt listing what was removed.
  • Before work begins, the agreement names what can be read, where approved outputs may be written, which processors are involved and how every grant is removed at offboarding. What was built stays in your accounts.

Where working files live

The main engagement folder and operating outputs live in a restricted workspace the client owns. Raw client records do not live in a VNMSFX personal drive, reusable repository or personal AI account.

If local processing is necessary, the temporary copy stays on an encrypted device outside cloud sync and source control. It is deleted after verified processing or transfer and no later than seven calendar days after creation.

A longer working-copy exception requires written client approval and cannot extend beyond 30 days from the original creation date. Raw client data in VNMSFX cloud backup is prohibited. Any unavoidable encrypted device-backup residual is disclosed and must age out within 60 days.

Client-owned records remain under the client's retention policy. AI and automation providers follow the exact retention and deletion terms named in the engagement data schedule.

Which AI products are used

The exact client-owned AI product, commercial mode, account owner, model, tools and retention settings are named in the data schedule before access. VNMSFX does not substitute another product or mode silently.

Personal consumer AI accounts never receive client data. Chat and API use are listed separately because they keep data differently.

How a wrong conclusion is stopped

AI may help extract, sort, classify, summarize and draft. It is not the source, calculator, accountant or approver.

Every important financial conclusion must link to the exact source records and period, show the repeatable rule or calculation, state what is missing and reconcile to an available trusted source total. If no reliable total exists, the conclusion stays qualified or blocked. Missing, stale, duplicate or conflicting records stop the answer or send it to review.

Finance-sensitive conclusions require the client's named finance reviewer. Until the evidence, repeatable check and review pass, the item stays marked Needs review and cannot trigger an action.

What I never need

Card numbers, bank credentials, Social Security numbers, or employee personal files. If a system holds them, access is scoped so they stay out of view.

Agreements, incidents & offboarding

The agreement, confidentiality terms and data schedule are automatic—not something the client has to request. VNMSFX accepts no credentials, private exports, accounting rows, customer data or confidential live screen-share before those terms are signed.

Offboarding is a checked sequence across the systems involved, not one universal button. VNMSFX transfers or freezes jobs, confirms client ownership, removes its identities, revokes or rotates accessible tokens, deletes permitted copies, records provider data-keeping periods and issues a written receipt.

Old access is tested wherever the provider permits testing; any untestable residual is named, dated and accepted in the receipt. The final test is simple: the client's trained operator can still run the accepted system after VNMSFX has been removed.

If anything ever goes wrong with client data, the written notification timetable and response steps in the signed agreement apply.
